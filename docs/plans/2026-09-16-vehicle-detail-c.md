## 1. 무엇을 정했나

**C안**: B의 **2×2 수치 타일과 상태 문구**에 A의 **앱바·밑줄 탭·기존 색 토큰**을 얹는다.

| 가져온 곳 | 요소 |
| --- | --- |
| B (Figma "fleet app management", CC BY 4.0 — **구조만** 참고, 파일·아이콘·이미지 미사용) | 네 계측값을 같은 위계의 타일로 · "지금 받은 값 / ○○시에 받은 값 · 현재 값 아님" 섹션 머리 · 지연·재연결 시 큰 숫자 비우기 |
| A (현재 앱) | `AppBar` + 밑줄 `TabBar` · `app_theme.dart` 색 전부 · `design_tokens.dart` 간격·모서리·글자 |
| 새로 | 긴 차량 이름의 **전체 이름 보기** · 기준 초과 개수(DTC 포함) |

**하지 않는 것** — 앱에 없는 기능(원격 시동·도어·비용·운전자·일정), 차량 사진, 색 띠 머리,

## 5. 반응형 — 폭 × 글자 배율

기존 경계를 그대로 쓴다: `Breakpoints.mobile` 600, `desktop` 1024, 최소 지원 폭 `Widths.compact` 320.

### 5-1. 배치

| 폭 | 좌우 여백 | 수치 타일 | 연료·스로틀 · DTC | 차트 · 지도 | 내용 최대 폭 |
| --- | --- | --- | --- | --- | --- |
| 320–359 | `context.screenPadding`(sm 12) | 2열, **단 타일 최소 폭 미달이면 1열** | 타일 아래 목록 | 한 열로 아래 | 제한 없음 |
| 360–599 | md 16 | 2열(2×2) | 타일 아래 | 한 열로 아래 | 제한 없음 |
| 600–1023 | md 16 | **4열 한 줄**, 최소 폭 미달이면 2열 | 타일 아래 2열(연료·스로틀 \| DTC) | 차트·지도 나란히 2열 | `ContentWidths.feed` 840 |
| ≥1024 | md 16 | 2×2 | 왼쪽 열 아래 | **2단**: 왼쪽(요약·타일·목록·DTC) / 오른쪽(차트·지도) | `ContentWidths.grid` 1200 |

- 상태 요약은 모든 폭에서 **맨 위 한 줄 전체**. 무엇이 먼저 읽혀야 하는지는 폭과 무관하다.
- 열 수는 `isDesktop` 같은 폭 분기만으로 정하지 않고 `LayoutBuilder`로 **실제 받은 폭**에서 계산한다:
  `columns = clamp(floor((w + gap) / (minTile + gap)), 1, 목표 열 수)`,
  `minTile = 148 × min(textScale, 1.5)` — 148은 "-40.0 °C"와 라벨이 1.0배에서 한 줄에 드는 폭으로, **구현 첫 단계에서 320/1.0으로 재서 확정**한다(추정값).
  폭 분기로 정하면 태블릿 분할 화면이나 2단 레이아웃 안처럼 "화면은 넓은데 받은 칸은 좁은" 경우를 놓친다.
- 1024 이상 2단의 좌우 비율은 7:5. 오른쪽이 `minTile × 2`보다 좁아지면 한 열로 되돌린다.

### 5-2. 긴 차량 이름

- 1.0~1.5배 전부: 제목 `maxLines: 2` + 말줄임.
- **실제로 잘렸는지** `TextPainter.didExceedMaxLines`로 판정해, 잘렸을 때만 ID 옆에 `전체 이름` 버튼(`TouchTarget.min` 48).
- 버튼 → 바텀시트(`Radii.lg`): 전체 이름(`SelectableText`) + 차량 ID. 복사 가능.
- 앱바 높이: 두 줄 + ID가 들어가도록 `toolbarHeight`를 글자 배율에 따라 계산. 1.5배·두 줄에서 `TabBar`와 겹치지 않는지가 테스트 항목이다.

### 5-3. 탭

- 지금 규칙 유지: 폭 < 400 또는 배율로 11pt가 14 초과면 스크롤 탭.
- 추가: 글자 배율 ≥ 1.3이면 탭 아이콘을 숨기고 글자만 — 1.5배에서 탭 한 줄이 앱바 높이를 가장 많이 먹는다(지금 골든은 구성 요소 갤러리라 탭이 없다 — 0단계에서 만든 1.5배 화면 스냅샷으로 확인 후 적용 여부 확정).

### 5-4. 가로 모드·키보드

- 가로 폰(높이 < 480): 앱바가 두 줄 이름으로 커지면 본문이 거의 안 남는다 → 높이 < 480에서는 제목 1줄로 줄이고 버튼 조건은 그대로.
- 이 탭에 입력창이 없어 키보드 영향 없음.

## 6. 단계 — 한 단계 = 한 커밋, 각 단계가 초록으로 끝난다

각 단계 끝에서 `dart format --set-exit-if-changed`, `flutter analyze`, `flutter test`(skip 외 전부 통과) 필수.
스냅샷은 5단계에서만 갱신한다.

### 0단계 — 기준선 스냅샷 (UI 변경 없음)

- 골든에 **상세 화면 전체** 스냅샷 추가: 가짜 STOMP로 `DashboardTab`을 live/over/stale 세 상태로 띄워 360 라이트·다크, 360 1.5배, 1280.
  지금 골든은 구성 요소 갤러리뿐이라(`design-system.md` "아직 안 한 것") 화면 전체 변화를 볼 수 없다.
- 이 단계 스냅샷은 **바꾸기 전 모습**을 남기는 용도다. 5단계에서 같은 이름으로 갱신하므로 diff가 곧 변경 설명이 된다.
- 완료: 새 골든이 Windows에서 통과, 기존 8장 불변.

### 1단계 — 기준값 한 곳으로 + view state (UI 변경 없음)

- `telemetry_limits.dart`, `dashboard_view_state.dart` 추가. `hasAnomaly`와 대시보드 리터럴이 이것을 읽게.
- 테스트(순수 Dart):
  - 경계값: 105.0 정상 / 105.1 초과, 6000 정상 / 6000.25 초과, 11.5·15.0 정상, 200 정상.
  - `overCount`: 온도만 1, 온도+DTC 2, DTC만 1, 없음 0.
  - freshness: 연결됨→live, 재연결→reconnecting, 10초 초과→stale(겹치면 stale 우선 — 지금 규칙).
  - `receivedClock`은 **수신 시각** 기준(차량 timestamp 아님).
- 완료: 기존 테스트 전부 그대로 통과(동작 불변 증명).

### 2단계 — 타일·상태 요약·지연 시 비우기 (G2, G3, G5, G6)

- `metric_tile.dart`, `metric_tile_grid.dart`, `extra_readings.dart`, `status_summary.dart` 추가, `_DashboardBody` 교체.
- `PrimaryMetricCard`·`SecondaryMetricCard`·`AnomalyBanner` 삭제, 해당 테스트 참조 교체.

| `나중 시각 frame은 정상 반영` :237 | 같은 문구 ×2 | 초과 타일 2개 | 정상 갱신이 막히지 않는다 |

- 문구로 찾던 것을 **`Key`로 찾는다**(`metric_tile_speed` 등). 문구를 다듬을 때마다 불변식 테스트가 깨지지 않게.
- 새 위젯 테스트: 과거 상태에서 차트 "수신 없음", 기준 초과 타일 `Semantics` label.
- 완료: 위 표의 불변식 전부 통과 + 전체 테스트 초록.

## 9. 이 계획 밖 (순서 후보)

1. 차량 목록 카드와 상세의 상태 표현 맞추기 — 목록의 정상·지연·오프라인(5·15분)과 상세의 live·stale(10초)은 **다른 기준**이다. 같은 단어를 쓰지 않도록 문구 정리.
2. 공통 상태 알약(`_SignalPill`, `_Badge`, `_SeverityBadge`, DTC 알약) 하나로.
3. 이상 이력 탭의 배지가 정적 `AppTheme.success/danger`를 써 다크에서 토큰을 안 따른다(`anomaly_list_screen.dart:76-88`), 같은 파일 108-110행 `anomalies.isEmpty` 중복 분기.
4. 주행 기록 탭 내용 폭 제한 없음.
5. D5 한글 글꼴, D7 웹 랜딩, D8 플랫폼·실기기 E2E.

## 10. 커밋 규칙

- 단계마다 커밋 하나. AI 공동저자 트레일러를 넣지 않는다. `마지막커밋:` 접두사를 쓰지 않는다.
- 푸시는 요청받았을 때만. 푸시한 커밋은 rebase·amend·force-push하지 않는다.
